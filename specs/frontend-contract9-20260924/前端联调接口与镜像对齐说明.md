## 2. 同源认证与通用请求

前缀 `/api/console/v1`，使用当前同源 HTTPS。浏览器通过 `POST /auth/login` 登录后携带会话 Cookie；写操作携带登录返回的 CSRF token，header 为 `X-CSRF-Token`。不将 Cookie、token 或密码写入联调文档。

- `GET /me`：读取当前账号；不根据页面上缓存的角色代替后端授权。
- `POST /auth/logout`：退出后清除当前 Run、问题、片段和来源卡片状态。
- 普通用户只能访问本人会话、Run、附件、来源。跨账号 Run/来源请求返回 404。
- 管理写接口仍使用 `Idempotency-Key`；消息使用 `client_request_id`，二者不是一个协议。
- 分页列表 `items/total/page/page_size`。保留旧接口原有结构；不要把所有列表都假定为分页。
- 错误读取 `code/message/field_errors/request_id`（部分历史错误可能只有兼容错误文案）。不要用中文 message 文本判断业务分支。

## 3. 能力声明与模型调用

`GET /capabilities?page=1&page_size=100`

```json
{
  "items": [], "total": 0, "page": 1, "page_size": 100,
  "message_support": {
    "version": "message-support-v1", "file_ids": true, "max_files": 5,
    "file_usage": "user_reference", "requires_ready": true,
    "allows_truncated": false, "plugin_ids": "preference", "skill_ids": "method",
    "manual_selection": false, "skill_dispatch": "native_tool"
  }
}
```

这是形状示例，实际 items 和可用状态由账号权限及环境决定。`file_ids=false` 或无此声明时关闭“随消息选择文件”，但资料库上传可以保留。旧规划模式不支持附件时声明为 false。

本轮保留候选契约的 `plugin_ids=preference`、`skill_ids=method` 兼容语义；`manual_selection=false` 表示当前产品界面不应提供手动附加能力入口。前端正常发送空 `skill_ids/plugin_ids`。不要把 `selectable_in_message` 当成产品要求恢复手动入口：它描述兼容 API 可接受性，界面服从 manual_selection。

每项能力仍含 `id/kind/name/version/available/enabled/owned/scope/dependency_ids/unavailable_reason`。`enabled` 不等于 available，更不等于已经调用。

### 3.1 个人 Skill 的模型调用闭环（r2）

1. 消息受理从当前账号已 applied 的个人 Skill 中，过滤停用、失效依赖和未生效配置。
2. 冻结有效目录的 ID、名称、版本、正文摘要哈希，并将方法正文保存在本轮加密快照。
3. 模型在需要时调用平台内置 `peixian_load_personal_skill`，参数只有 `skill_id`。它不是第九个业务资料插件，不向上游取数。
4. 加载时再次检查账号、Run、取消状态、配置版本、技能归属、版本、正文哈希和依赖；失败不冒充加载成功。
5. 实际加载保存 `skill_calls` 和持久执行事件；执行过程展示技能 ID/名称/版本。相同 call_id 同技能不重复追加事件，换技能返回冲突。

模型仍负责决定是否使用方法；目录可发现不等于每次必须调用。原生通用文件/命令工具不会为加载技能而开放。Skill 文本不能授予资料权限。

公共模板仍需复制到个人空间。旧个人副本的依赖失效会单独显示不可用，不覆盖原文，也不因其存在阻止其他有效方法。账号 A 实测存在 3 个可用个人 Skill 与若干旧依赖失效副本；这是配置状态，不是接口故障。

## 5. 文件与消息受理

文件上传仍走 `POST /files` multipart；`GET /files/{fid}` 轮询解析。必须 ready、非 truncated、有可用正文且属于本人。最多 5 个；文件引用最多 24000 字符；文本、技能与文件总量仍受 18000 UTF-8 字节限制，服务端权威判定。

```http
POST /api/console/v1/sessions/{sid}/messages
Content-Type: application/json
X-CSRF-Token: <当前会话 token>
```

```json
{
  "text": "请整理所附资料中明确记载的内容",
  "agent_id": "theft-assistant", "mode": "standard",
  "file_ids": ["file-example"], "skill_ids": [], "plugin_ids": [],
  "client_request_id": "71d88fe9-9c85-476b-94d4-45d1947e30ac"
}
```

202：`{"accepted":true,"run_id":"run-example","message_id":"msg-example"}`。

同账号、会话、请求标识及内容返回原受理结果；同键不同内容返回409。网络断线不能换一个随机键自动重发。页面保存原 client_request_id，明确查询是否已受理。

消息的 `attachments[]` 包含 `id/name/status/parse_status/content_sha256/text_bytes/chunk_count/usage/verified_source`。文件名称和正文来源被冻结；文件后来删除时附件可变为 unavailable，但历史内容不重新读文件或调用模型。`usage=user_reference`、`verified_source=false`，不得标成已核验来源或据此扩大查询范围。

| code | HTTP | field_errors 中的典型值 |
|---|---|---|
| file_not_found | 404 | 文件ID：not_found |
| file_not_ready | 409 | 文件ID：not_ready |
| file_truncated | 413 | 文件ID：truncated |
| file_text_empty | 409 | 文件ID：empty_text |
| file_parse_invalid | 409 | 文件ID：invalid_chunks |
| file_budget_exceeded | 413 | 文件ID：budget_exceeded |
| message_budget_exceeded | 413 | text：预算限制 |

前端可按文件ID将错误显示在 chip；在尚未支持逐字段展示时至少显示服务端安全 message，不静默删除附件后发送。

## 6. 缺项问答与多选

`GET /questions` 返回 `{"items":[...]}`，按 sessionID 过滤当前会话。新增 `question_version`，每题新增 `question_id/selection_min/selection_max/skippable/skip_effect`，每个选项新增 `option_id`。这些都是附加字段，原有 label 提交兼容。

```json
{
 "id":"q-example", "sessionID":"ses-example", "question_version":"内容摘要",
 "questions":[{
   "question_id":"q-example:0", "header":"位置", "question":"请明确本次位置",
   "multiple":false,"selection_min":1,"selection_max":1,
   "skippable":false,"skip_effect":"reject_group","custom":false,
   "options":[{"option_id":"q-example:0:摘要:0","label":"已取得的位置甲"}]
 }]
}
```

提交 `POST /questions/{id}/reply`：

```json
{"question_version":"内容摘要","answers":[["已取得的位置甲"]]}
```

- `/reply` 仍按题目顺序提交 label 字符串数组；**option_id 本轮仅用于稳定 UI 身份，不是可直接替换 answers 的提交值**。
- multiple 缺省或 false：最多1项。true：允许多项；后端验证全部值，不静默取第一项。可自填题允许自由文本。
- `too_many_answers`、`duplicate_answers`、`invalid_answer`、`clarification_incomplete` 返回422；带旧 question_version 返回 `question_changed` 409。
- selection_min=1；不支持逐题空数组跳过。整组不回答调用 `POST /questions/{id}/reject`，JSON `{}`。
- 来源/人员/经纬度/半径/时间等预检补充题始终单值。取消不继续该待执行查询，也不增加资料调用。
- 题目内容不变时 question_version 和 option_id 保持不变；变化则刷新选择，不将旧选项映射到新题。

缺项工具返回 needs_input 后，模型使用 question 提问；已有有效条件保留。来源或字段真正变化时重新确认对应项。真实失败仍返回错误，不全部转成提问。

原生工具 Run 的 `run.clarification` 返回 null，走 `/questions`，避免和 `theft-clarification-v1` 重复显示。旧规划 Run 的 clarification 协议保留；旧会话不迁移为新协议。结果后的 `next_question` 仍是普通自然语言追问入口，不是批准查询的结构化指令；多选相互矛盾或条件不足时由模型澄清，再经服务端校验。

## 7. 统一错误及调用统计

工具客户端到 Control/Gateway 使用安全 `tool-failure-v1`：

```json
{
 "version":"tool-failure-v1","code":"source_selection_required",
 "message":"请选择本次抓拍使用的位置来源；已提供的时间和半径仍可保留。",
 "stage":"precheck","dispatch_status":"not_dispatched",
 "field_errors":{},"recovery_action":"select_source","call_id":"call-example"
}
```

主要 recovery_action：clarify、select_source、check_capability、reconcile、stop。字段值不包含用户原始身份号码、内部地址或堆栈。未知错误使用安全通用文案并保留调用标识。

预检拒绝、等待补充不计实际资料调用。`dispatch_status=unknown` 不能显示“尚未查询”或自动重发。Run 完成不代表所有资料调用成功；业务失败不能改成零记录。

保持当前自动允许机制，本轮没有恢复独立模型意图核对。

## 8. Run、消息快照和资料片段时序

前端继续只用 `/sessions/{sid}/messages` 完整快照渲染正文；无需另接增量接口。`source_answer` 与 `final_answer` 是不同稳定消息/part，不互相覆盖。

- source message：`msg_delivery_{run_id}`。
- source part：`part_delivery_{run_id}_{sequence}`。
- 来源片段在插件结果合同核对完成的同一保存事务中追加；下一次消息快照可读取，不等到所有工具执行结束。
- 单片段不可变，sequence 递增；重复快照按 message/part ID 替换或合并，不追加副本。
- 不能承诺固定网络时延上界；仍需轮询及 SSE 通知补查。
- `Run.status` 决定执行状态。`status_revision` 防止旧响应覆盖新状态；`event_sequence` 是另一种序号，不混用。
- `answer_delivery.final=true` 仅表示片段流关闭；不代表成功。result_saved 指示最终结果已保存。

时序：发送202 → GET Run/事件 → GET messages 可见来源片段 → 终态及 result_saved → GET result/最终消息。

取消：POST Run abort → cancelling → 确认 cancelled。失败或取消保留已取得片段。reconciling/unknown 不自动重发。断线恢复只 GET，不重放 POST。

可选增量：`GET /sessions/{sid}/runs/{rid}/answer-segments?after=0&limit=100`，版本 controlled-segments-v1，items 含 sequence/content_revision/part_id/operation/text/source_ids/claim_ids。after 为最后应用序号，limit 1–100；游标超前409 sequence_ahead。旧 Run status=unavailable，保持原消息。未来如改用增量，必须替换快照归并路径，不并行渲染两套正文。

## 9. 来源卡片、详情和图谱

终态 `GET /sessions/{sid}/runs/{rid}/result` 的 `presentation`：

```json
{"version":"source-clues-v1","status":"ready","revision":"内容摘要","clues":[],"missing":[]}
```

形状示例不表示 ready 可无来源；正常无卡片状态为 empty。clues 字段详见 OpenAPI。仅已批准逐条事实与对应记录、快照匹配时构建。模型自由文本或文件引用不能直接生成卡片。警情 cjsj 仍是处警时间，不改成案发时间。

详情新增：

`GET /sessions/{sid}/runs/{rid}/sources/{evidence_id}`

```json
{
 "version":"source-detail-v1","run_id":"run-example",
 "evidence":{"id":"source-example","source_run_id":"run-example","record_id":"record-example","snapshot_id":"snapshot-example"},
 "record":{"record_id":"record-example","snapshot_id":"snapshot-example","fields":{}},
 "versions":{}
}
```

这里 rid 是持有该 presentation 的 Run；根据 evidence_id 精确返回其中已保存的公开记录。响应示例省略了其他必需 evidence 字段，完整结构看 OpenAPI 和 samples。记录不存在、旧结果无此版本、跨账号均404；不读取最新供应方数据，不补造历史结果，不返回原始上游密钥或正文诊断。

evidence.id 来自 source_run_id 与 record_id 的稳定摘要；revision 来自卡片内容摘要。终态数据不会因页面刷新产生新 revision。前端不自行用索引或模型标题定位来源。

图谱仍使用：

- `GET .../graphs`：列表。
- `GET .../graphs/{gid}`：详情。
- `GET .../graphs/{gid}/nodes/{nid}`：节点。
- 原 expand/paths/analysis/query 路径保持；方法及参数以 OpenAPI 为准。

只增加明确的人员—来源记录归属边，不推断人与人关系。ready=存在可用图；partial=有图但有缺口；empty=没有可投影关系；pending=结果未结束；unavailable=历史结构不支持。卡片非空不必然图谱非空。

## 10. 报告与历史兼容

报告沿用 `GET /sessions/{sid}/runs/{rid}/report?format=md` 或 html，保留原 Content-Disposition。报告读取保存结果，不增加模型或上游调用。旧 Run 不补建片段、卡片、技能调用或新图谱，也不批量改写历史名称和文字。

未知 answer/presentation 版本不提升为可信展示。前端保留已有可支持结果，并提示版本暂不支持。

## 11. 前端需要继续做的事项

1. 保持 r7 样式及现有消息快照方案，不同时消费 answer-segments。

6. 复核同一 Run 切换、断线恢复、取消和资料片段不重复，390px 表格区域内横向滚动。
