# 盗窃助手对话简化与补充问答交接

本次将普通用户的资料查询入口统一为对话输入。用户直接描述目标和已有条件；服务端规划器在本账号已授权的能力内决定一次受控查询。聊天页不再要求手工选择插件、Skill 或具体接口，也不在输入区显示人工来源复核表单与“执行结束”横幅。来源复核、步骤、可信结果和报告的后端记录与接口继续保留。

## 补充问答

当规划器缺少一个必要条件时，`GET /api/console/v1/sessions/{sid}/runs/{rid}` 的 `clarification` 返回 `version=theft-clarification-v1`、稳定问题 `id` 与 `missing` 字段。前端使用现有 OpenCode 风格问答卡逐项显示中文问题。答案作为同一会话的新用户消息提交，沿用当前任务；新消息仍需要新的 `client_request_id`。问答卡不直接调用资料接口。

`POST /api/console/v1/sessions/{sid}/runs/{rid}/clarification/reject` 表示“暂不回答”，只关闭当前待补充问题，不查询资料或调用模型。两条接口均按会话本人鉴权；旧 Run 的 `clarification` 为 `null`。当前实现复用问答卡视觉与交互，规划问题由持久任务投影，未把它伪装成 OpenCode 的原生 `question` 工具调用。

前端用中文标签将范围答案写回消息。经度、纬度、半径、明确的开始或结束时间、页码和来源编号在服务端重新解析与校验。对于“近期”“仅盗窃”等上游不支持的条件，只有用户选择“同意使用上游默认覆盖范围”才可继续；不作默许或自动扩大查询。来源编号必须属于当前任务已核对的来源记录，不能默认选第一条。

## 结果与边界

同一任务的原目标、补充条件和已确认的来源关系保存在加密任务记录中。每次实际资料查询仍冻结参数、来源和授权，失败或结果未知不自动重试。聊天页保留已核对的事实、处理过程、图谱和报告入口；结果正文不因隐藏输入区技术控件而改变。历史会话和个人空间中的插件、Skill 管理能力不删除。

本次只简化盗窃助手的普通聊天体验，没有新增真实资料接口、人员嫌疑评分或自动扩大检索范围。验证需分别核对源码测试、部署镜像、实际问答交互和真实资料联调；其中任一项不能代替其余项目。
