# 八插件 Mock 调用修复与联调记录

## 修改范围

本轮修复的是原生插件调用链路，不修改业务接口路径、不扩大权限，不访问真实供应方。七合一及旧发布不恢复，八项独立插件仍为 3.0.0。

- 部署工具发现私密目录中的 `console-provider.json` 时，以只读文件挂载至 `/run/secrets/provider-config`，通过 `PX_THEFT_REAL_CONFIG_FILE` 传递；配置缺失继续默认关闭。
- 出口合同支持按插件 kind 配置独立连接，仍兼容 police/warning 旧分组。验证绑定的连接 ID、版本、方法与路径；不会随意选择另一连接。
- 半径支持“周边500米”“周围300米”“半径为0.3公里”，仍拒绝多个范围、非整数米和模型扩大参数。
- Gateway 和 Agent 工具桥对白名单预检错误明确返回 `not_dispatched`，不公开内部错误正文。
- Run 调度器从冻结 native_tool_policy 核对已授权工具；不再套用旧固定计划的空允许表，也不在同 Run 后续调用时丢失先前允许工具。越权工具仍触发取消。
- 前端聚合状态区分运行、完成、失败、取消和待核对；不改布局或样式。
- 独立意图核对为空或无法解析时，不放行资料查询，持久标记 rejected/not_dispatched。规划输出 token 上限改为 `PX_PLANNING_MAX_TOKENS`（默认4096，允许256–16384），保留超时、响应大小、独立回执及不自动重试。新增 finish_reason 诊断字段。不能将增大上限视为模型永不返回空内容的保证。

## 部署与接口兼容

普通消息、Run、证据接口路径不变。私有 `native_review_failed` 只关闭绑定的未批准核对，不授予执行权限，不重新投递。历史 Run 不重写。

私密出口配置包含测试账号范围、八项连接 ID、合成夹具对象指纹、批准坐标范围及资源限制；不包含连接凭据。实际八条连接均固定到服务器私有 Mock，真实服务未启用。当前底层合同字段沿用 `acceptance_real`，这表示合同适配路径，不能据此认定数据是真实业务资料；本轮数据来源以已核对的 Mock 连接为准。

未来重建此站点必须使用本分支修复后的 platform-manage.py 并保留 `runtime/secrets/console-provider.json`。只设置账号能力开关不足以启用出口。该文件不进入 Git、普通日志或前端。
