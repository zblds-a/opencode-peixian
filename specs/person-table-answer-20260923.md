# 盗窃助手人员信息与四段式表格接入说明

## 1. 展示与适用范围

新原生工具 Run 冻结 `table_answer_policy.version=person-tables-v1`。资料回答在聊天中按“人员基本信息、基本结论、判断依据、下一步分析建议”展示 Markdown 表格；不新增下载功能。问候和缺项问答仍自然对话。旧 Run 不回填、重算或替换正文，原报告接口保持原有契约。

模型选择工具和来源，并以结构化选择提出最多三项建议；代码执行来源归属、快照和字段检查、表格转义与持久化。模型前置文字不作为表格事实。建议选择包括核对已有来源、补充缺项和进一步查询已授权模块，不自动执行。

## 2. 数据获取与复用

人员信息使用八插件中的 `peixian_query_profile`，上游为 `GET /caputer/profile/{idCard}`。只对已确认的唯一人员调用；已有同一任务、同一人员档案优先引用。所有查询保持代码预检、独立意图核对、插件及出口校验。多项用户目标允许逐工具完成，不要求一个工具一次完成整项任务。

原生模型可能同时提出多个工具调用。Gateway 按会话与父消息有界串行接入，每个等待槽最多8项、等待120秒；每次获取槽后重新执行原有受理和授权检查。取消中的等待不投递，未知结果不自动重发。此限制是资源保护，不是业务调用额度。

历史来源仅从本人本会话同任务的持久结果中取出，经原摘要完整性检查，并按冻结查询的人员引用匹配。范围为最近50次执行、模型历史上下文最多120000字节；触及边界明确记录缺口，不声称完整覆盖。新旧来源保留原 Run 与快照，不按相同时间或字段合并记录。不同版本档案并列保留来源和取得时间。

## 3. 接口增量

现有消息和 `GET /api/console/v1/sessions/{sid}/runs/{rid}/result` 入口不变，数据库仍为v11。Result V2 新增可选 `answer_view`：

| 字段 | 类型 | 含义 |
|---|---|---|
| version | string | 固定 person-tables-v1 |
| run_id | string | 本次展示所属执行 |
| person_ref | string/null | 本会话内脱敏人员引用，未确认时为空 |
| status | string | ready/partial，存在资料局限时保留说明 |
| basic | array | label/value/source_ids/source_run_id/obtained_at |
| conclusions | array | text/source_ids/source_run_id/claim_id/limitation，最多5条 |
| evidence | array | module/label/time/text/source_ids/source_run_id/snapshot_id |
| suggestions | array | text/reason/conditions/source_ids/origin/action/kind，最多3项，origin为model_selection |
| missing | string[] | 未取得、未知、来源限制及历史覆盖缺口 |
| preview_count/total | integer | 默认预览最多10条与已取得记录数，不是上游总量 |
| source_runs | string[] | 引用的原执行编号 |
| markdown | string | 与本版本四部分结构一起持久化的兼容正文；刷新不重新生成 |
| selection_status | string | accepted/fallback；格式失败使用代码事实，不代表取数失败 |

消息读取返回平台生成的 text Part，origin 保持 controlled_answer，正文与持久 answer_view 对应。生成期间不公开结构化JSON或模型临时事实文字；已确认工具状态正常显示。展开记录与来源使用本地 details，不发起模型或资料请求。

模型可引用记录编号或同一来源Run中的快照记录组；不存在的编号不采纳。代码不从模型给出的句子中抽取事实。人员基本信息仅使用允许公开的档案字段；不生成未提供住址、职业，人员编号沿用脱敏引用。
